## アプリ概要

ruby on railsで作る、グループ単位のタスク管理・日報アプリ。個人タスクを作成し、進捗をコメントで日々報告していく形。CRUD機能が中心で外部APIに依存しないため、初チーム開発の題材として選定。

- **[機能案]** postsをtasksに変更。日報はtaskへのコメントとして記録する
- **[機能案]** tasksの担当者は1人固定（個人タスク）

## 9/7で決めること

### 01. groups.owner_id案（role列を持たせない方針）で確定してよいか

グループの管理者（招待コードの再発行やグループ名変更ができる人）をどう表現するかの論点。

| 案 | 利点 | 懸念 |
| --- | --- | --- |
| owner_id案（今の提案） | groups.owner_id == user.idの一行で管理者判定ができる／group_membersに列が増えないので実装がシンプル／権限チェックのロジックが単純でレビューもしやすい | 管理者は常に1人固定。複数人に管理権限を持たせたくなったら設計変更が必要 |
| role列案 | group_membersにowner / memberを持たせれば複数管理者や権限の細分化に対応しやすい／メンバー一覧取得時に権限情報も一緒に取れる | enum定義や権限チェックロジックが増える分、実装コストが上がる／MVPでは使わない権限管理を先に作り込むことになりやすい |

## 分担案（たたき台）

依存関係（users→groups→tasks→comments）があるため、土台部分は全員で固めてから機能ごとに分岐する。

### 進め方（更新版・9/4時点）

- **groups機能**：しょせ・toma・カンちゃんの3人で、アクション単位（new/create・show・destroy）に分担して同時進行
    - しょせ：new / create
    - カンちゃん：show
    - toma：destroy
- **ひー**：機能を横断して、先に固定HTML（Tailwindでのデザイン）を作成。その後3人がそれぞれの担当アクションのビューをERBに落とし込む
- 次の機能（tasks等）でのローテーションは未定。9/7でひーと相談した方向性を共有する

---

### なぜこの形にしたか

- 足並みを揃えて同じ機能に取り組むことで、お互いのPRをレビューしやすくなる
- new/create・show・destroyは依存性が薄く、並行して進めやすい
- ひーさんの強み（フロントエンド）を活かしつつ、Rails経験が浅い彼女に無理にモデル/コントローラーを書かせない

---

### 懸念とその対策

- 同じコントローラー・同じビューディレクトリを複数人で触るため、機能ごと担当制よりコンフリクトが起きやすい → こまめな小さいPR、routes.rbの先行整備で軽減
- コンフリクト解消自体を経験として許容する方針

#### ステップ1：準備週（全員）

- 5テーブル分のマイグレーション・アソシエーションを先に一通り作成
- 認証（Devise）は準備週のうちにしょせが実装する。これにより第1週〜第3週をGroup・Task・Commentそれぞれ1週間ずつに充てられる
- ひーの固定HTML（Tailwindでのデザイン）は、認証画面（ログイン・サインアップ）も含めて先に用意する
- db:seedで最小限のダミーデータ（グループ・タスク）を用意しておく

**なぜseedが必要か**

groupsをアクション単位（new/create・show・destroy）で分担する進め方のため、show・destroy担当者はnew/createで作られたレコードがないと動作確認ができない。準備週のうちに`Group.create!`などで最小限のダミーレコードを用意しておくことで、各担当者が着手初日からすぐ動作確認できるようにする。

ruby

```ruby
# db/seeds.rbgroup = Group.create!(name: "テストグループ", invite_code: "abc123", owner: User.first, is_personal: false)
```

rails db:seed を各自のDocker環境で実行すれば、UI（画面）を経由せず全員が同じダミーデータを使える。seeds.rbはgitで共有するので、4人とも同じデータで開発できる。

## サイドバー：参加グループの表示（Discord風）

参加しているグループ一覧をサイドバーに常時表示する。indexアクションを別途作らず、ヘルパーメソッドまたはApplicationControllerのbefore_actionで一覧を取得する。

```ruby
# app/controllers/application_controller.rb（before_action案）
class ApplicationController < ActionController::Base
  before_action :set_sidebar_groups

  private

  def set_sidebar_groups
    @sidebar_groups = current_user&.groups
  end
end
```

is_onlyの個人グループができたことで、サイドバー上では「個人グループ」と「参加中のチームグループ」を視覚的に分けて表示する必要がある（ひーのHTML設計で意識してもらうポイント）。
